## 总体风险

1. `functions/run_all.py` 原先只要无 `FAIL` 就把总结果写为 `PASS`，即使存在 `SKIP`。已修正为存在 `FAIL` 或 `SKIP` 时总结果为 `FAIL`。
2. `mempool/FN-1` 旧结果为 `SKIP`，原因是 `REQUIRE_PEER=1` 且 `peer_alive=false`；已收紧脚本并在双节点重跑 PASS。`mempool/FN-3` 旧结果同样因 peer 不在线跳过，已新增 `RPC_MEMPOOL_POOLS` 并在双节点重跑 PASS，不再用单节点或历史 OOB 字段证明统一命名。
3. `rdma/FN-4` 已完成真实 GPU Direct RDMA 闭环：xfusion4 暴露 CUDA GPU MR，xfusion3 通过 RDMA WRITE/READ 访问该 GPU MR，xfusion4 使用 CUDA kernel 做 GPU 侧内容校验。
4. `storage/FN-4` 已新增运行时去重统计和验收脚本，并已在 `2026-05-04T11:57:54+0800` 生成 PASS 证据。
5. `storage/FN-6` 已把脚本和数据面统计增强为 WAL 文件解析、ObjectAttr/InteractionEvent 类型校验，并已在 `2026-05-04T12:16:58+0800` 重新生成 PASS 证据。

## 视频或答辩说明文案

本项目围绕“网存算一体化硬件基础支撑子系统”实现了三类核心能力。第一类是多级异构存储，C++ 数据面提供 DRAM、NVMe、HDD 统一层级接口，支持对象在层级间迁移、读时提升、顺序/Markov 预取、冷层压缩、运行时去重、前后台 I/O 调度，以及仿真运行中对象属性和交互事件采集。对应验证入口在 `functions/storage/FN-1` 到 `FN-6`，多数通过 UDS 直接调用数据面 RPC；其中 FN-4 已完成重复对象去重统计和 HDD 读回闭环，FN-6 已完成 WAL 内容级验收，证明 ObjectAttr 和 InteractionEvent 两类事件均真实落盘。

第二类是 RDMA 分布式通信。数据面初始化 32 个 QP，通过 TCP/OOB 完成端点、slab base、rkey、QPN 等元数据交换，并在 PUT 路径使用 RDMA WRITE 复制到 peer；同时实现批量 PUT、高低优先级 QP 调度、一致性哈希路由查询，以及 GPU Direct RDMA。RDMA FN-4 使用 xfusion4 的 `cudaMalloc` GPU buffer 注册 RDMA MR，由 xfusion3 通过 RDMA WRITE 写入并 RDMA READ 读回，xfusion4 通过 CUDA kernel 校验 GPU 显存内容，证明 CPU 只提交 WR，payload 由 RNIC 直接进入 GPU 显存。路由功能目前证明的是路由决策和负载分布，不是完整的按路由远端转发数据面。

第三类是一致性总线内存池化。数据面以 slab pool 和 PoolRegistry 暴露分布式内存池 API，支持 UDS PUT/GET 闭环、tenant/pool ACL 隔离，并在 peer 在线时使用 RDMA WRITE 同步远端内存；HA 方面提供 heartbeat、peer_alive、degraded_puts、degraded_bytes 字段，显式开启时可做 peer 故障降级演练。`mempool/FN-1` 已通过 `RPC_KV_PUT_RDMA transport=rdma degraded=false`、peer slab base/len/rkey/QP 元数据、offset/size 范围和 `RPC_TCP_GET_PEER` 同值读回证明双节点 RDMA 远程内存访问闭环；`mempool/FN-2` 已通过普通 `RPC_KV_PUT -> RPC_KV_GET` 和 peer 读回证明封装 API 屏蔽 RDMA 细节但真实落到 peer 副本；`mempool/FN-3` 已通过 `RPC_MEMPOOL_POOLS` 证明本地和远端共享 slab 均登记为 `default/slab1k`，且 registry 元数据与 OOB/cluster 的 RDMA MR 元数据一致；`mempool/FN-4` 已通过 `RPC_MEMPOOL_ADAPT_PUT/GET/STATS` 证明冷对象先放置到远端 RDMA slab，连续访问达到热点阈值后迁移到本地 slab，并由普通 `RPC_KV_GET hit=local` 证明热点数据本地化；`mempool/FN-5` 已通过双租户同名 key 测试证明 ACL 授权/撤销和租户命名空间隔离；`mempool/FN-6` 已通过主动 kill peer 证明故障期间本节点 degraded PUT 与本地 GET 继续可用，降级计数递增，恢复后重新进入 RDMA 非降级复制并完成 peer 读回。

整体上，当前项目不是 UI 或脚本 mock：功能验收主要直连 C++ 数据面 UDS 并保存 raw/summary 证据。需要注意的是，部分 RDMA 功能测试仍按“基本完成”表述其边界，例如批量传输、优先级调度和路由转发不替代正式性能收益证明。
