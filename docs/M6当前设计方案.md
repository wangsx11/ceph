# M6 分级存储 - 当前设计方案

## 一、架构概览

### 1.1 三层存储定义

| 层级 | 存储介质 | Ceph Pool/路径 | 特性 | 持久性 |
|------|---------|---------------|------|--------|
| **热层 (Hot)** | 内存 (DRAM) | `/mnt/hot` (ramfs) | 访问速度最快 | ⚠️ 断电丢失 |
| **温层 (Warm)** | SSD | `warm_pool` | 访问速度中等 | ✓ 持久化 |
| **冷层 (Cold)** | HDD | `cold_pool` | 访问速度最慢 | ✓ 持久化 |

### 1.2 数据组织方式

**当前设计：缓存模式（复制策略）**

```
┌────────────────────────────────────────────────────────┐
│                      数据写入                           │
│                          │                             │
│                          ▼                             │
│              ┌─────────────────────┐                   │
│              │      温层(100)      │ ← 写入初始层      │
│              │      (SSD)          │                   │
│              └──────────┬──────────┘                   │
│                         │                              │
│         ┌───────────────┼───────────────┐              │
│         │               │               │              │
│         ▼               │               ▼              │
│  ┌────────────┐         │      ┌────────────┐         │
│  │  热层(10)  │         │      │  冷层(40)  │         │
│  │ (内存)     │         │      │ (HDD)      │         │
│  └────────────┘         │      └────────────┘         │
│       ▲                 │              ▲              │
│       │                 │              │              │
│       └─────  温层(100) ───────────────┘              │
│              (保留完整副本)                            │
└────────────────────────────────────────────────────────┘
```

**关键特征：**
- 数据下沉/提升时采用**复制策略**（不删除源层数据）
- 温层始终保留**所有100个对象**作为完整备份
- 热层和冷层是温层的**缓存副本**
- 数据可能同时存在于多层

## 二、数据迁移机制

### 2.1 提升操作（Promotion）

#### Hot ← Warm（高频数据）
```python
# _promote_warm_to_hot()
1. 从 warm_pool 读取数据
2. 写入 /mnt/hot/对象名
3. ❌ 不从 warm_pool 删除（保留副本）
4. 记录迁移事件："温层(SSD) → 热层(DRAM)+温层"
```

#### Warm ← Cold（访问回升）
```python
# _promote_cold_to_warm()
1. 从 cold_pool 读取数据
2. 写入 warm_pool
3. ❌ 不从 cold_pool 删除（保留副本）
4. 记录迁移事件："冷层(HDD) → 温层(SSD)+冷层"
```

### 2.2 下沉操作（Demotion）

#### Hot → Warm（热度降低）
```python
# _demote_hot_to_warm()
1. 从 /mnt/hot/ 读取数据
2. 写入 warm_pool
3. ❌ 不从 /mnt/hot/ 删除（保留副本）
4. 记录迁移事件："热层(DRAM) → 热层+温层(SSD)"
```

#### Warm → Cold（长期未访问）
```python
# _demote_warm_to_cold()
1. 从 warm_pool 读取数据
2. 写入 cold_pool
3. ❌ 不从 warm_pool 删除（保留副本）
4. 记录迁移事件："温层(SSD) → 温层+冷层(HDD)"
5. ⚡ 触发快照（见下文）
```

### 2.3 热度计算

```python
def calculate_heat_score(obj_id):
    """基于访问频率和时间衰减计算热度"""
    score = Σ (1 / (1 + time_diff) ^ α)

    参数：
    - TIME_DECAY_ALPHA = 0.3  # 衰减系数
    - TIME_WINDOW = 7200      # 时间窗口(秒)

    阈值：
    - THRESHOLD_HOT = 5.0     # 热层阈值
    - THRESHOLD_WARM = 2.0    # 温层阈值
    - DEMOTE_HOT = 3.0        # 热层下降阈值
    - DEMOTE_WARM = 0.5       # 温层下降阈值
```

## 三、快照机制

### 3.1 触发条件

**自动触发**：数据从温层下沉到冷层时
```python
# _demote_warm_to_cold() 成功后
if self._demote_warm_to_cold(name):
    demoted.append(name)

# 在步骤4中统一创建快照
self._create_snapshot(demoted)
```

### 3.2 快照内容

```python
def _create_snapshot(self, demoted_objs):
    snap_name = f"snapshot_{timestamp}"

    # 保存元信息（非完整数据）
    snapshot_data = {
        obj_id: {
            "size": len(data),
            "hash": compute_hash(data)
        }
        for obj_id in demoted_objs
    }

    # 保存到文件
    ~/ceph-web/data/snapshot_YYYYMMDD_HHMMSS.json
```

### 3.3 快照展示

- 快照名称、时间戳、对象数量
- 生成耗时统计
- 支持点击查看详情

## 四、演示流程（6步骤）

```
步骤0: 清理旧数据
        │
        ▼
步骤1: 写入100个对象 → 温层(SSD)
        │
        ▼
步骤2: 模拟访问
        ├─ 10个高频访问 (15-25次)
        ├─ 20个中频访问 (3-6次)
        └─ 70个不访问
        │
        ▼
步骤3: 冷热识别迁移
        ├─ 高频 → 热层(10个)
        └─ 无访问 → 冷层(40个)
        │
        ▼
步骤4: 冷数据快照
        └─ 为下沉到冷层的40个对象创建快照
        │
        ▼
步骤5: 回访回迁
        └─ 部分冷数据被访问 → 提升回温层
        │
        ▼
步骤6: 再次分层
        └─ 持续热度监测，自动分层
```

## 五、数据持久性与一致性

### 5.1 断电场景分析

| 场景 | 热层 | 温层 | 冷层 | 总数据 | 是否可恢复 |
|------|------|------|------|--------|-----------|
| **断电前** | 10个 | 100个 | 40个 | 150个副本 | - |
| **断电后** | 0个 | 100个 | 40个 | 140个副本 | ✓ 可恢复 |

**恢复机制：**
- 热层数据丢失，但温层有完整数据
- 系统重启后从温层重新提升热数据
- 应用层读取时使用 `cache_read()` 逐层查找

### 5.2 存储空间分析

```
初始状态：
- 温层: 100个 × 4KB = 400KB

迁移后状态（缓存模式）：
- 热层: 10个 × 4KB = 40KB
- 温层: 100个 × 4KB = 400KB (未删除)
- 冷层: 40个 × 4KB = 160KB
- 总计: 600KB (1.5倍冗余)
```

## 六、关键问题与风险

### 6.1 当前设计问题

1. **温层始终包含所有数据**
   - 冷层实际作用被弱化
   - 存储空间利用率不高

2. **断电后热层丢失**
   - 虽可恢复，但需重新预热
   - 短期内访问性能下降

3. **快照意义不明确**
   - 冷层本身已是持久化存储
   - 快照保存的是元信息而非完整数据

### 6.2 架构争议点

| 问题 | 当前方案 | 替代方案 |
|------|---------|---------|
| 数据重叠 | 允许（缓存模式） | 禁止（分层模式） |
| 温层角色 | 完整数据存储 | 中间过渡层 |
| 冷层作用 | 归档+备份 | 纯容量层 |
| 快照目的 | 元信息记录 | 未知/待确认 |
