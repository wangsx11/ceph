# 性能展示原始结果解读

本文用于讲解 `/performance-dashboard/` 中“原始结果”页签。目标是把性能 JSON 中真正证明达标的指标挑出来，避免现场从完整日志里寻找重点。

## 前端读取链路

- 页面入口：`/performance-dashboard/`
- 前端显示位置：`../performance_dashboard/fn_runner.js`
- 原始结果内容：`materialContent("原始结果")` 对 `detail.raw` 执行 `JSON.stringify(detail.raw, null, 2)`
- 详情 API：`GET /api/performance/fn/performance/<PF-ID>`
- 控制面选择逻辑：`control_plane/app.py::_latest_performance_result`

性能前端同样不直接读固定日志文件，而是由详情 API 返回 `raw`。控制面会在以下来源中选最新结果：

1. 单项基线：`performances/<PF-ID>/raw.json`
2. 单项前端执行历史：`performances/<PF-ID>/history/web_*/raw.json`

详情 API 还会根据 `raw` 生成 `evidence`，前端“验收结论”面板展示的就是这些证据。“原始结果”页签仍然显示完整 `raw` JSON。

## 通用讲解顺序

1. 先说 `passed=true`、`status=PASS`。
2. 再讲 `evidence` 中的第一条，它通常是该性能点的主指标。
3. 然后讲零失败、零降级或阈值字段，说明结果不是只跑出了数字，而是满足验收条件。
4. `raw_*` 字段通常是底层命令原始输出，现场不需要展开，除非被追问复现实验细节。

后续如果做前端高亮，建议统一加粗或着色这些字段：`passed`、`status`、`evidence`、主指标字段、失败/降级字段、阈值字段。
