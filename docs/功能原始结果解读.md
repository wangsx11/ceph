# 功能展示原始结果解读

本文用于讲解 `/function-dashboard/` 中“原始结果”页签。目标是把杂乱的 JSON 结果收敛成现场可以直接说明的成功证据，并给后续前端高亮提供字段清单。

## 前端读取链路

- 页面入口：`/function-dashboard/`
- 前端显示位置：`../function_dashboard/fn_runner.js`
- 原始结果内容：`materialContent("原始结果")` 对 `detail.raw` 执行 `JSON.stringify(detail.raw, null, 2)`
- 详情 API：`GET /api/functions/fn/<module>/<fn_id>`
- 控制面选择逻辑：`control_plane/app.py::_latest_function_result`

前端不是直接读某一个固定日志文件，而是由详情 API 返回 `raw`。控制面会在以下来源中选最新结果：

1. 单项基线：`functions/<module>/<FN>/raw.json`
2. 单项前端执行历史：`functions/<module>/<FN>/history/web_*/raw.json`
3. 全量执行汇总：`functions/raw.json` 或 `functions/history/web_all_*/raw.json` 中对应行

因此，讲解时不要从 `run.log` 开始讲。先看 `status`、`completion`、`passed`、`evidence`，再按本文列出的关键字段补充说明。

## 通用讲解顺序

1. 先说 `status=PASS`、`completion=完成`。
2. 再读 `evidence` 数组，这是脚本已经整理好的成功证据。
3. 需要展开原始 JSON 时，只展开 `details` 下的关键字段。
4. `log`、`run_json`、`raw_json` 只作为追溯来源，不作为现场主讲内容。

后续如果做前端高亮，建议统一加粗或着色这些字段：`status`、`completion`、`passed`、`evidence`，以及下表“重点字段”中的字段路径。

## 前端高亮建议

如果后续改前端“原始结果”展示，建议不要整段 JSON 全部着色，而是按以下规则高亮：

- 成功结论：`"status": "PASS"`、`"passed": true`、`"completion": "完成"`。
- 人类可读证据：`"evidence"` 数组整段加粗。
- 模块关键字段：按上表字段路径加粗，例如 `details.batch.ok_n`、`details.gdr_validate.mismatches`、`details.capture_stats.flushed_events`。
- 对 `mempool/FN-6` 额外高亮 `before.peer_alive -> mid.peer_alive -> recovery_status.peer_alive`、故障期间 `put_during_outage.degraded=true`、恢复后 `post_recovery.put.degraded=false` 与 `post_recovery.peer_get.ok=true`，说明这是完整主动故障演练。
