# RDMA 硬件配置摘要

采集时间：2026-04-27  
用途：记录 `native_rdma` 自研分布式共享数据系统当前双节点演示环境的关键参数。本文只保留会影响部署、启动、NUMA 绑定、分级存储路径和性能判断的信息。

## 1. 节点拓扑

| 项目 | 节点 A | 节点 B |
|---|---|---|
| 主机名 | `xfusion3` | `xfusion4` |
| RoCE IP | `192.168.0.218/24` (`ens2np0`) | `192.168.0.214/24` (`ens6np0`) |
| RDMA 设备 | `mlx5_0` | `mlx5_0` |
| 网卡 | ConnectX-5 (`MT4119`) | ConnectX-5 (`MT4119`) |
| 链路 | Ethernet / RoCE / LinkUp | Ethernet / RoCE / LinkUp |
| 标称速率 | 100 Gb/sec | 100 Gb/sec |
| IPv4 RoCEv2 GID index | `3` | `3` |
| HCA NUMA node | `0` | `1` |
| OS | Ubuntu 20.04.6 LTS | Ubuntu 22.04.5 LTS |
| 内核 | `5.15.0-139-generic` | `5.15.0-171-generic` |

结论：两台机器满足当前 `native_rdma` 双节点演示的 RDMA 基础条件。数据面配置应固定使用 `RDMA_DEV=mlx5_0`、`GID_IDX=3`。

## 2. RDMA 基线

测试参数：`mlx5_0`、GID index `3`、RoCEv2、active MTU `1024`。

| 方向 | RDMA WRITE 平均带宽 | MsgRate | 平均延迟 | P99 |
|---|---:|---:|---:|---:|
| A -> B | 57.39 Gb/sec | 0.109 Mpps | 1.74 us | 1.77 us |
| B -> A | 41.86 Gb/sec | 0.080 Mpps | 2.06 us | 2.10 us |

注意事项：

- 两端 `perftest` 版本不同，直接互跑可能出现版本兼容报错；需要压测裸链路时，优先使用同版本二进制。
- active MTU 当前为 `1024`，不是最大 `4096`。如后续追求更高带宽，MTU 是可检查项。

## 3. CPU / NUMA / 内存

| 项目 | 节点 A | 节点 B |
|---|---:|---:|
| 逻辑 CPU | 80 | 64 |
| Socket | 2 | 2 |
| Core / socket | 20 | 16 |
| NUMA node | 2 | 2 |
| HCA NUMA | node0 | node1 |
| 内存 | 2.0 TiB | 755 GiB |
| 可用内存 | 1.9 TiB | 694 GiB |
| hugetlb HugePages | 未预留 | 未预留 |

部署约束：

- 节点 A 的数据面 poller / RDMA 相关线程优先绑定 NUMA node0。
- 节点 B 的数据面 poller / RDMA 相关线程优先绑定 NUMA node1。
- 当前环境没有预留 hugetlb HugePages；`native_rdma` 启动脚本默认使用较小 slab 规模，避免演示时强依赖大页预留。

## 4. 存储与演示路径

| 资源 | 节点 A | 节点 B |
|---|---|---|
| DRAM 热层 | 由 `SLAB_TOTAL_BYTES` 控制，默认演示 4 GiB | 由 `SLAB_TOTAL_BYTES` 控制，默认演示 4 GiB |
| Warm 路径 | `/dev/shm/native_rdma_warm` | `/dev/shm/native_rdma_warm` |
| Cold 路径 | `/home/wangshouxin/nr_cold` | `/tmp/nr_cold` |
| Cold 容量配置 | 20 GiB | 10 GiB |

关键约束：

- 节点 B 的 `/home` 空间紧张，冷层不要放在 `/home`。
- 当前分级存储演示使用 `deploy/node_a.env` 和 `deploy/node_b.env` 中的路径；如调整目录，优先修改 env 文件，不要硬编码到脚本里。

## 5. 当前部署配置入口

| 文件 | 作用 |
|---|---|
| `native_rdma/start.sh` | 当前新实现的一键同步、编译、清理、双节点重启入口 |
| `native_rdma/deploy/node_a.env` | 节点 A 的 IP、RDMA、NUMA、分层路径、迁移阈值 |
| `native_rdma/deploy/node_b.env` | 节点 B 的 IP、RDMA、NUMA、分层路径、迁移阈值 |
| `native_rdma/scripts/demo_up.sh` | 单节点演示栈启动入口：数据面 + Flask 控制面，由 `start.sh` 调用 |
| `native_rdma/scripts/demo_down.sh` | 演示栈停止入口 |
| `native_rdma/scripts/start_node.sh` | 单独启动 C++ 数据面 |

当前推荐启动方式：

```bash
cd native_rdma
bash start.sh
```

底层双节点启动顺序由 `start.sh` 执行：

```bash
ssh xfusion4 "cd $PROJECT_ROOT/native_rdma && ROLE=B bash scripts/demo_up.sh"
cd native_rdma
ROLE=A bash scripts/demo_up.sh
```

浏览器访问节点 A Flask 地址，默认 `http://192.168.0.218:5000/`。

## 6. GPU 状态

| 项目 | 节点 A | 节点 B |
|---|---|---|
| GPU | 无可用 NVIDIA 驱动 | A100 80GB + A800 80GB |
| GPU/HCA NUMA | 不适用 | 都在 NUMA node1 |
| GPU/HCA 拓扑 | 不适用 | `SYS`，不是近邻拓扑 |

当前 `native_rdma` 演示主线不依赖 GPU。若后续实现 GPU 直通，需要单独验证 peer memory、GDRCopy 和真实吞吐。
