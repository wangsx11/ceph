# 性能测试术语问答

本文档记录性能测试讲解过程中容易被问到的专业术语，用于后续准备答辩、视频旁白或演示说明。

## 数据面是什么？

“数据面”指系统里真正处理数据读写、复制、传输、调度和存储的核心执行层。

在本项目里，数据面具体指 C++ 进程：

```text
native_rdma_dp
```

它和 Flask、dashboard 这些控制面或展示层不同。控制面负责发指令、展示状态、编排演示；数据面负责真正干活。

数据面的主要职责包括：

- 接收对象 PUT/GET 请求。
- 写入本地 slab 内存池。
- 通过 RDMA 将对象复制到 peer 节点。
- 执行批处理传输。
- 执行 QoS 高低优先级调度。
- 处理多级存储读写。
- 运行仿真引擎相关 RPC。
- 输出性能指标到 shared-memory metrics。

可以简单理解为：

```text
控制面 = 管理和展示
数据面 = 真正搬数据、处理请求、跑性能热路径
```

性能测试中的 `nr_bench` 会通过本机 Unix Domain Socket 连接数据面：

```text
/tmp/native_rdma-dp.sock
```

请求路径大致是：

```text
nr_bench -> /tmp/native_rdma-dp.sock -> native_rdma_dp -> 内存池/批处理/QoS/RDMA/存储
```

## nr_bench 是什么？

`nr_bench` 是本项目的数据面压测工具，全称可以理解为 native RDMA benchmark。

它是一个 C++ benchmark 二进制，通常位于：

```text
native_rdma/build-current/bin/nr_bench
```

它的作用是直接向 C++ 数据面发送高频 PUT、GET、batch PUT 等请求，用来测量数据面热路径的吞吐、时延、批处理能力和 RDMA peer 复制能力。

`nr_bench` 不经过浏览器页面，也不经过 Flask HTTP 控制面。它通过 Unix Domain Socket 直接连接数据面：

```text
/tmp/native_rdma-dp.sock
```

这样可以减少控制面和 HTTP 的干扰，让性能测试更接近数据面真实热路径。

常见用法示例：

```bash
native_rdma/build-current/bin/nr_bench \
  --uds=/tmp/native_rdma-dp.sock \
  --op=put \
  --threads=8 \
  --val-size=1024 \
  --duration=10 \
  --require-peer=1
```

这些参数的含义是：

- `--uds=/tmp/native_rdma-dp.sock`：连接哪个数据面 UDS socket。
- `--op=put`：执行 PUT 写入请求。
- `--threads=8`：使用 8 个压测线程。
- `--val-size=1024`：每个对象大小为 1KB。
- `--duration=10`：压测 10 秒。
- `--require-peer=1`：要求请求必须成功经过 RDMA peer，不能接受本地降级结果。

`nr_bench` 输出中常见字段包括：

- `ops/s`：每秒成功对象操作数。
- `ops ok/fail`：成功和失败请求数量。
- `ops degraded`：本地降级请求数量。
- `req_bytes`：客户端向数据面发送的请求字节数。
- `resp_bytes`：数据面返回给客户端的响应字节数。
- `latency us`：成功请求的平均时延和分位时延。

在性能测试中，`nr_bench` 被用于多个 PF：

- PF-1：测试 1KB 小对象吞吐，以及大对象 RDMA 网络带宽压测输入。
- PF-2：测试 1KB 对象端到端时延。
- PF-3：测试高低优先级 QoS 传输效率。
- PF-4：测试批量聚合传输总耗时。
- PF-5：测试批处理吞吐。
- PF-6：测试 1MB 对象读写带宽。

一句话概括：

```text
nr_bench 是绕过前端和 Flask、直接压测 C++ 数据面的性能测试工具。
```
